Flexible CSV Column Order — Explanation
----------------------------------------

The requirement states that input CSV files may not have columns in the expected order (e.g., in
Customer_List_PA1.CSV, ID is not column 1, First Name is not column 2, etc.).

BEFORE (hardcoded indices — breaks if columns are reordered):

    int id = Integer.parseInt(fields[0].trim());        // always assumes ID is column 0
    String firstName = fields[1].trim();                 // always assumes First Name is column 1

If someone provided a CSV like:
    Username,First Name,Password,ID,Last Name,User Type,...
The old code would try to parse "Username" as an integer ID and crash.

AFTER (dynamic header mapping — works regardless of column order):

1. buildColumnMap() reads the header row and creates a lookup table:
       "id" -> 3, "first name" -> 1, "username" -> 0, "password" -> 2, ...

2. The loader uses that map instead of hardcoded numbers:
       int id = Integer.parseInt(fields[col.get("id")].trim());           // goes to index 3
       String firstName = fields[col.get("first name")].trim();           // goes to index 1

So if the CSV has ID in column 5 and First Name in column 8, the code finds them by NAME not
position. The columns can be in any order and it still reads the correct data.

This approach is applied to all three loaders:
- loadUsers() — maps "id", "first name", "last name", "username", "password", "user type", etc.
- loadEvents() — maps "id", "type", "name", "date", "time", "vip price", etc.
- loadVenues() — maps "id", "name", "type", "capacity", "concert capacity", "cost", etc.


Preserving CSV Column Order on Write
--------------------------------------

The requirement also states that when the program writes data back to CSV, the column order must
match the original input file — not a hardcoded default order.

BEFORE (hardcoded write order — overwrites the original column order):

    writer.println("ID,Type,Name,Date,Time,VIP Price,...");    // always writes this order
    writer.printf("%d,%s,%s,%s,%s,...", event.getEventID(), event.getType(), ...);

If the input had columns as Date,ID,VIP Price,Type,... the output would rearrange them to
ID,Type,Name,Date,... which changes the file layout.

AFTER (preserves original column order):

1. On load, the original header string is stored in a field (userHeader, eventHeader, venueHeader).

2. On write, the stored header is written first. Then for each record, the code iterates through
   the header columns in their original order and uses a helper method to look up the correct
   value for each column name:

       writer.println(eventHeader);                          // writes "Date,ID,VIP Price,Type,..."
       for each column in header:
           line.append(getEventField(columnName, event));    // maps "date" -> event.getDate(), etc.

3. Helper methods (getEventField, getUserField, getVenueField) use a switch on the lowercase
   column name to return the correct field value from the object.

This means if the input has "Date,ID,VIP Price,Type,..." the output will have the exact same
column order — not a hardcoded default. The approach is applied to all three writers:
- writeUsers() — uses getUserField() and userHeader
- writeEvent() — uses getEventField() and eventHeader
- writeVenues() — uses getVenueField() and venueHeader
